Executive summary

The application is feature-complete as a demo: inbox, clients, properties, matching, calendar, pipelines, documents, WhatsApp webhook, voice, AI auto-reply and settings all work end-to-end against mocks. Getting it client-ready is three parallel tracks:

① Make it real

Swap mocks for live credentials — Claude API, WhatsApp Business, S3 storage, speech-to-text — and verify each round-trip in production.

② Make it safe

Restore real authentication (the demo gate was removed), turn on webhook signature checks, lock down storage, size the database, add backups & monitoring, and address UAE PDPL data handling.

③ Make it theirs

Build the seven requested workstreams: contact tagging, Agents/Investors sections, owners database, reporting, template→PDF storage, video/floorplan storage, and bulk PDF send.

Read first — two things will bite at handover if ignored

1. The access gate is currently OFF. We removed the demo password so the live link is open. Before a real client touches production, proper per-user authentication must be restored (see §2). 2. The database seed plants demo data for the developer's email on every fresh deploy — a production tenant must start clean (see §3).

1 · Integrations & credentials — flip from demo mode to live

Everything below is wired behind adapters already; production readiness here means provisioning accounts, obtaining secrets, setting them in the Render dashboard, and verifying the live round-trip. Set all secrets in Render → Environment, never in the repo.

1.1 Anthropic Claude Integration

  • Provision an Anthropic API key with production rate limits; set ANTHROPIC_API_KEY and (optionally) ANTHROPIC_MODEL (defaults to claude-opus-4-8).
  • Verify classification, urgency, summarise, requirement-extraction, command bar, auto-reply and reply-suggest all hit the real model — the heuristic mock in src/server/ai/mock.ts silently takes over when the key is missing, so confirm logs show real calls.
  • Cost guardrails — set a monthly spend alert; consider caching and a cheaper model for high-volume classification vs. Opus for drafting.

1.2 WhatsApp Business Cloud API Integration Longest lead time

This is the critical-path integration — Meta review and template approval can take days. Start it first.

  • Meta Business account verified; create a WhatsApp Business Account (WABA) and register the business phone number (it cannot already be on the consumer WhatsApp app).
  • Permanent token — create a System User and generate a non-expiring access token → WHATSAPP_ACCESS_TOKEN. Capture WHATSAPP_PHONE_NUMBER_ID and WHATSAPP_BUSINESS_ACCOUNT_ID.
  • Webhook — point Meta at https://<your-domain>/api/whatsapp/webhook, set WHATSAPP_VERIFY_TOKEN (GET challenge) and WHATSAPP_APP_SECRET (so inbound payload signatures are verified — currently optional, must be ON in prod).
  • Message templates — submit and get approval for every proactive/outbound-outside-24h template (follow-ups, viewing invites, brochure delivery). Bulk PDF send depends on this.
  • Display name & quality — get the display name approved; understand your messaging tier (1K → 10K → 100K → unlimited) and how to ramp.
  • Verify a real inbound message creates a conversation + runs AI analysis, and a real outbound (free-form within 24h, and template outside it) delivers.

1.3 AWS S3 storage Integration Data-loss risk if skipped

Render's disk is ephemeral

Anything written to local disk (uploaded documents, and the new floorplans / videos / generated PDFs / templates) is wiped on every redeploy. S3 is not optional for production — it's a blocker.

  • Create a private bucket; set AWS_REGION, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, S3_BUCKET. The getStorage() adapter switches from local disk to S3 automatically once these are present.
  • Serve private files through signed URLs (already proxied via /api/files/[id]); set a bucket policy that blocks public access.
  • Add a lifecycle rule for large media (videos) and confirm WhatsApp-downloaded media is persisted to S3 (download tokens expire fast).

1.4 Speech-to-text (voice notes) Integration optional

  • Set SPEECH_TO_TEXT_PROVIDER + SPEECH_TO_TEXT_API_KEY (OpenAI Whisper supported) to transcribe inbound WhatsApp voice notes server-side. Without it, browser dictation still works but inbound voice notes won't auto-transcribe.

1.5 App URL & portals Integration

  • NEXT_PUBLIC_APP_URL = the real domain (used in invite/brochure links).
  • Property Finder / Bayut import are stubs today. If live portal import is in scope, real API/scrape credentials and per-portal adapters are additional work — confirm whether it's needed for handover.
  • BROKER_NUMBER for info-pack/broker routing.

4 · WhatsApp production rules — these shape the features

Why this matters for "send PDFs to multiple clients"

WhatsApp only lets you message a contact freely within 24 hours of their last message to you. Outside that window you may only send pre-approved template messages. So bulk PDF send must: (a) use an approved template for cold recipients, (b) attach the PDF as a document, (c) respect per-second rate limits and your messaging tier, and (d) honour opt-in. This becomes a throttled queue, not a simple loop.

  • Template approval for every proactive message type; maintain a template library mapped to the in-app sender.
  • Opt-in / consent capture and an unsubscribe path.
  • Per-recipient media upload to WhatsApp (or hosted URL) with retry; throttle to tier limits; surface delivery/read receipts.
  • Quality-rating monitoring — bulk sends to unengaged contacts can degrade the number's rating.

6 · New feature workstreams New

The seven requested edits, each a self-contained chunk in BUILD-NEXT.md. Guiding principle throughout: this is a primary communication system, not a CRM — every feature hangs off the WhatsApp conversation and stays lightweight.

16
Unified contacts + tagging — schema foundation for everything after it

Introduce a single Contact record with a category: Client, Agent (external broker), Investor, Spam, Personal. Conversations link to a Contact. The existing Client becomes a Contact with category=client; lead-only fields (budget, pipeline) just stay empty for other categories. Inbox gains tag chips + filter-by-tag.

17
AI auto-tagging — suggests, agent confirms

Extend the existing classification layer to predict the contact category on inbound, show it as a one-tap suggestion the agent can accept or override. Spam tag mutes/filters the conversation.

18
Agents & Investors sections

Dedicated filtered views (and nav items) for the Agent and Investor categories, each with category-appropriate fields — e.g. investors get target areas / ticket size / asset type; external agents get agency, areas covered. No heavy CRM screens.

19
Owners database — bulk upload + search

A new Owner model with Excel/CSV import (owner name, phone, email, area, building, unit, notes). Fast search/filter by area & building; one-tap WhatsApp/call from a result. Standalone reference list (not auto-linked to listings).

20
Reporting & analytics

A metrics dashboard: total WhatsApp messages broken down by category (client / investor / agent…), incoming leads, viewings booked, response time, pipeline conversion. Date-range filter; aggregation queries + charts.

21
Storage hub — templates, floorplans, videos

(1) Editable templates with merge fields ({{property.price}}, {{property.area}}…) that render branded PDFs from live property data; (2) floorplan storage; (3) video files & links. All persisted to S3.

22
Bulk PDF send

Generate a PDF from a template + property, pick multiple contacts, and send via WhatsApp through a throttled, template-compliant queue (see §4). Delivery status per recipient.
